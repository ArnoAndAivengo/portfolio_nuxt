В [первом посте](/articles/learnportal-tehblog-01) обещал разобрать, как устроены курсы в `course-content/` и почему контент живёт в файлах, а не сразу в админке. Этот выпуск — про **зачем** так сделано и **как** собрать курс: от папки на диске до страницы `/courses/...`.

## Зачем Markdown, а не сразу БД

ТЗ требует: добавлять курсы должно быть дёшево. На практике это значит:

- методист пишет в обычном редакторе, а не в десятках полей админки;
- правка абзаца не требует релиза фронта;
- история изменений — в git: кто, когда и зачем поменял тему;
- контент и платформу можно держать отдельно (отдельный репозиторий или сервер — в планах).

База нужна для рантайма: прогресс ученика, XP, ответы на квизы, запись на курс. Исходники уроков — в файлах. Между ними sync: файлы читаются, курс в PostgreSQL обновляется, прогресс при обычном sync **не сбрасывается**.

Публичный справочник `/docs` и курсы платформы — разные системы. Теорию можно переиспользовать через `source` в `theory.md`. Обычно автор пишет материал сразу под обучение.

## Иерархия: язык → курс → модуль → тема

Каталог строится так, чтобы линейка языка (HTML, потом CSS, JS…) читалась глазами в репозитории. На платформе у каждого курса свой `slug` и URL.

```
course-content/
  <язык>/                      # html, css, javascript, …
    <N-курс>/                  # порядковый номер в линейке
      course.json              # метаданные + slug платформы
      modules/
        <NN-модуль>/
          module.json
          <N-тема>/
            theory.md
            quiz.md
            practice.md
            bonus.md
            homework.md
```

Сейчас по HTML:

| Папка | Курс на сайте | `slug` |
| --- | --- | --- |
| `html/1-html/` | HTML: начальный | `html` → `/courses/html` |
| `html/2-html-intermediate/` | HTML: средний | `html-intermediate` |
| `html/3-html-advanced/` | HTML: продвинутый | `html-advanced` |
| `html/4-…` … `8-…` | Email, SEO, perf, CI/CD, проекты | в плане |
| `css/`, `javascript/`, … | другие линейки | заготовки |

**Папка на диске и slug — разные вещи.** В репозитории удобно `1-html`, `2-html-intermediate` — так виден порядок. В `course.json` лежит идентификатор платформы (`html`, `html-intermediate`). Именно он уходит в БД и в URL.

У **курса** — только `course.json`. У **модуля** — только `module.json`. Так проще не перепутать уровни.

## Зачем дробить на три (и потом восемь) курсов

Один огромный «весь HTML» плохо учится: новичок тонет в формах и SVG, пока ещё не уверен в тегах. Поэтому линейка режется по уровням:

1. **Начальный** — первая страница, теги, семантика и основы доступности (модули 01–03).
2. **Средний** — формы, медиа, таблицы, HTML5 API (04–07).
3. **Продвинутый** — микроразметка, SVG, a11y, производительность (08–12).
4. **4–8.** Email, SEO, производительность «в бою», CI/CD, проекты — отдельные курсы, пока папки-заготовки.

Внутри каждого курса модули снова нумеруются с `01-…`. Сквозная нумерация линейки (04–07) живёт в голове методиста и в документации. В папке курса порядок локальный и совпадает с `order` в `module.json`.

## Одна тема = один учебный шаг целиком

Эталон:

```
html/1-html/modules/01-introduction/1-getting-started-with-html/
  theory.md      # теория
  quiz.md        # проверка понимания
  practice.md    # код в браузерном редакторе
  bonus.md       # опциональное ★
  homework.md    # работа локально, без XP
```

**Одна папка = одна тема.** Ученик видит тему в оглавлении один раз и проходит цепочку:

| Шаг | Файл | Зачем |
| --- | --- | --- |
| Теория | `theory.md` | Объяснить идею и показать примеры |
| Опрос | `quiz.md` | Закрепить до практики |
| Практика | `practice.md` | Сделать руками в редакторе |
| Бонус | `bonus.md` | Углубить желающим (можно пропустить) |
| Домашка | `homework.md` | Вынести в VS Code / реальную среду |

Методист собирает не «какой текст положить в урок», а **какой путь проходит ученик по этой теме**.

Числовой префикс папки темы (`1-…`, `2-…`) совпадает с `order` в `theory.md`. Порядок виден и в файлах, и в БД после sync.

## Метаданные: что лежит в JSON и YAML

### Курс — course.json

```
{
  "title": "HTML: начальный курс",
  "slug": "html",
  "short_description": "С нуля до первой полноценной HTML-страницы.",
  "difficulty_level": "beginner",
  "category_slug": "html",
  "is_free": true,
  "is_published": true,
  "requirements": ["…"],
  "learning_outcomes": ["…"]
}
```

После sync эти поля видны на карточке курса: требования, результаты, уровень — без правок Vue.

### Модуль — module.json

Заголовок, описание, `order` внутри курса. Папка вида `01-introduction`.

### Тема и задания — frontmatter в .md

```
---
title: Первая HTML-страница
slug: html-intro-getting-started
description: Разбираем базовую структуру HTML-документа.
order: 1
duration_minutes: 40
xp_reward: 40
---
```

У заданий — те же поля плюс тело с блоками ````quiz` или ````code-config` (JSON прямо в markdown). Парсер собирает из этого уроки в БД.

`theory.md` — контейнер темы, не отдельное задание в прогрессе. На карточке курса:

- **уроки** = число тем;
- **задания** = quiz / practice / bonus / homework;
- **часы** = сумма минут по заданиям.

Цифры на сайте отражают программу, а не количество файлов в git.

## Как контент попадает на платформу

```
файлы в course-content/
        │
        ▼
  парсер (course.json → модули → темы → задания)
        │
        ▼
  sync (upsert по slug / content_key)
        │
        ▼
  PostgreSQL  ──API──►  /courses/<slug>
        ▲
  прогресс ученика сохраняется при обычном sync
```

Авторский цикл короткий:

1. Скопировать эталонную тему (или модуль).
2. Написать `theory.md` и задания.
3. Синхронизировать: админка **«Курс из файлов»** → **Синхронизировать**, или CLI.

```
cd backend
npm run sync:html                 # html/1-html
npm run sync:html-intermediate
npm run sync:html-advanced
npm run sync:html-all             # все три
```

Полный сброс курса (`replace` / «Пересоздать») — отдельный режим: он удаляет структуру и прогресс. Для правок текста достаточно sync.

Перезапуск контейнера сам по себе БД не обновляет: после `git pull` нужен именно sync.

## Что это даёт продукту

- Курсы можно вести как контент: ветки, ревью markdown, релизы линейки.
- Платформа остаётся продуктом обучения: прогресс, геймификация, плеер.
- Новые языки и курсы 4–8 добавляются той же схемой папок.
- Методист и разработчик говорят на одном языке: «модуль 02, тема 3, practice» — это видно и в git, и в админке.
