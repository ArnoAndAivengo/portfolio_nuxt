В [вводном посте](/articles/learnportal-tehblog-01) разбирали три требования: дешёвая поддержка, дешёвые курсы и современный стек.
Во [втором посте](/articles/learnportal-tehblog-02) — как контент живёт в Markdown.

Сегодня — про **четвёртое требование: прозрачность разработки**.

Нужно в любой момент понимать, *что уже сделано*, *что в работе* и *жив ли стенд* — без созвона «расскажи, как дела».

Сразу скажу, как обстоят дела **сейчас**.

Отдельного сервера, который открывается из интернета, **пока нет**. Он будет. На нём соберу тот же набор: GitLab, CI/CD, nginx, стенды, мониторинг. 
Пока вся инфраструктура живёт на **локальном сервере** в домашней сети. С него и веду разработку.

## Что значит «прозрачность» на практике

Так как это обучающая платформа, я буду писать, по всем правилам разработки.
Бизнесу нужны простые ответы:

| Вопрос | Где смотреть сейчас | Как будет на отдельном сервере |
| --- | --- | --- |
| Что менялось на этой неделе? | Коммиты в GitLab, `devDocs/CHANGELOG.md` | То же, уже с внешнего URL |
| Собирается ли код? | Pipeline в GitLab / GitHub Actions | Pipeline + выкладка на стенд по кнопке |
| Какие задачи в спринте? | Трекер TaskNebula | Тот же трекер, доступный команде и бизнесу |
| Можно ли потрогать продукт? | Локальный LearnPortal в Docker | **dev / stage / prod** за nginx |
| Жив ли сервис? | Prometheus, Grafana, дашборд сервера | Те же дашборды, уже снаружи |

## Что уже стоит на локальном сервере

Локальный сервер — homelab: **Docker + PM2**, Ubuntu.

Сверху — точка входа, чтобы не запоминать порты:

- **Portal** (`:80`) — главная страница со ссылками на сервисы;
- **Homepage** (`:8091`) — дашборд Docker-контейнеров.

Дальше — то, без чего прозрачность не работает.

### Git и CI

**Self-hosted GitLab** (`:8929`, SSH `:2224`): репозиторий, права доступа, merge request'ы, Container Registry.

Секреты в git не кладу. Это правило останется и на будущем сервере.

### Мониторинг

- **Prometheus** (`:9090`) — собирает метрики;
- **Grafana** (`:3005`) — дашборды: uptime, нагрузка, диск;
- **System Monitor** (`:8081`) — температуры, RAM, диск;
- **PM2 Status** (`:8082`) — какие Node-процессы живы.

Серьезная структура. Построение заняло много времени (около 2-3 месяцев)

### Трекер

Внутренние задачи — в **TaskNebula** (`:8102`): доска, бэклог, статусы.

### Docker и данные

- **Portainer** (`:9000`) — контейнеры;
- **Adminer** (`:8080`) — БД в браузере;
- **MinIO** — S3 на своём диске;
- **File Browser** — файлы на `/mnt/storage` (бэкапы, загрузки, медиа).

Рядом с платформой ещё крутятся вещи, которые позже пригодятся: **Judge0** (запуск кода), 
**Ollama** (локальный LLM), **code-server** (VS Code в браузере).

nginx-proxy на локальном сервере тоже есть: HTTPS и `*.local` внутри сети. Это черновик того, как будет вход снаружи.

## Как на этом сервере крутится LearnPortal

Платформа поднимается Docker Compose из своего репозитория.

| Сервис | Порт | Роль |
| --- | --- | --- |
| `frontend` | **5192** | Nuxt 3 |
| `backend` | **3000** | Express API, `/health`, `/api/v1` |
| `postgres` | **5433** | PostgreSQL 18 |
| `redis` | внутри сети | кэш и сессии |

Запуск простой: `docker compose up -d`. Документация разработчиков — `devDocs/`, на стенде это `/developers/docs`. История изменений — `CHANGELOG.md`.

Прод-файл `docker-compose.prod.yml` в репозитории уже есть: postgres, redis, backend, frontend, nginx. Сейчас он не смотрит в интернет. Это заготовка под отдельный сервер.

## Какой будет отдельный сервер

Когда он появится, не буду собирать стек с нуля. Перенесу то, что уже обкатано локально:

1. **Один вход снаружи** — nginx на `:80` / `:443`, TLS, домен.
2. **Три стенда** — dev, stage, prod. LearnPortal за прокси, без открытых `:3000` и `:5192` в интернет.
3. **GitLab CI/CD** — push → сборка образов → тесты → ручной деплой на стенд.
4. **Те же дашборды** — Prometheus, Grafana, трекер, CHANGELOG.
5. **Тот же стек приложения** — Node, PostgreSQL, Redis, Nuxt, Docker Compose. Без Kubernetes «на вырост».

Подготовка хоста: Docker, firewall только 22/80/443, отдельный пользователь `deploy`, каталоги под бэкапы и логи.

Типичные грабли, которые уже знаю по локальному контуру и которые обязательно всплывут снаружи:

- **`NUXT_PUBLIC_*`** попадают в бандл на **build**, не при restart контейнера;
- **healthcheck** у Postgres/Redis — иначе backend стартует раньше базы;
- **nginx `proxy_pass`** и слэши: `/api/v1/...` должен доехать как `/api/v1/...`;
- **бэкап до миграций** — сломанная миграция блокирует API.

Про это напишу отдельно, когда сервер появится. Пока фиксирую: схема понятна, железа с публичным IP ещё нет.

## Что в итоге на сегодня

Пока набор локальных ссылок:

- GitLab — коммиты и pipeline;
- CHANGELOG и `devDocs` — что задумано и что уже сделано;
- трекер — спринт;
- локальный LearnPortal — пощупать продукт;

Отдельный сервер из интернета добавит к этому внешний URL и нормальные стенды.

Такая вот архитектура. Но, все работает и живет круглосуточно. Позже все это уедет на отдельный сервер — уже со всеми технологиями из этого списка.
