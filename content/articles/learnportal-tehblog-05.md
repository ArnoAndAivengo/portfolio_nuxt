Отрисовка уроков и скорость подачи контента пользователю - одна из самых сложных и главных задач. 
Это не просто отрисовать текст в браузере - это доставить весь материал урока пользователю в целости и сохранности.

В урок будут входить картинки, видео и текст - это большой объем информации.

## Как грузятся MD-файлы

Структуру папок разбирал во [втором выпуске](/articles/learnportal-tehblog-02). Коротко путь такой:

```
course-content/   (theory.md, quiz.md, practice.md, bonus.md, homework.md)
        │
        ▼
     парсер
        │
        ▼
  sync в PostgreSQL
        │
        ▼
      API
        │
        ▼
  плеер (markdown-it → HTML)
```

Запуск:

- в админке: кнопка **«Курс из файлов»** → **Синхронизировать**;
- или из консоли: `npm run sync:html` (есть и для других курсов).

Парсер читает frontmatter и тело. Блоки ````quiz` и ````code-config` вырезает из текста и кладёт в отдельные поля. В `lessons.content` остаётся **Markdown**, не HTML.

## Что отдаёт API

Два разных запроса — (`GET /courses/:id/modules`) и (`GET /lessons/:id`)

**Карточка курса** — не тяжелые. Идут без текста уроков. Так и должно быть.

**Оглавление** (`GET /courses/:id/modules`) — дерево модулей и тем. Текстов теории там нет. 
Но сейчас туда же утекают `code_hint`, `code_solution`, `code_tests`, `code_files`. Для сайдбара это лишнее.

**Открытие урока** (`GET /lessons/:id`) — полное тело урока. Вместе с уроком отдаём соседей по теме, чтобы не дёргать API на каждый клик внутри темы.

## Как рисуется урок

Это не Nuxt Content. Уроки рендерит **markdown-it** в браузере: Markdown → HTML → `v-html`.
Поверх — подсветка кода, таблицы, глоссы с озвучкой английских слов через Web Speech API.

На обычной теме парсинг не заметен. Тормоз появляется раньше: после вызова API.
Если теория разрастётся до простыни — будем смотреть и оптимизировать.

## Что будет, если добавить картинки

Сейчас в уроках нет картинок и видео.

Если просто написать в Markdown `![](./scheme.png)`?

- парсер запишет эту строку в `content` как есть;
- markdown-it нарисует `<img>`;
- относительный путь **ни во что не резолвится**. Картинка не откроется, пока это не нормальный URL.

Если класть картинки рядом с `.md` в git?

- репозиторий раздувается на каждый скрин;
- каждый sync гоняет те же байты по кругу;
- картинку добавить в запрос? нет - этого делать не стоит.

Если вшивать картинки в сам Markdown (base64) или тащить их в поле `content`?

- `GET /lessons/:id` становится тяжёлым;
- браузер сначала качает JSON с картинками внутри, потом рисует урок;
- кэш страницы и кэш картинки — это уже один ком, его нельзя раздать по CDN отдельно.

Картинки тянуть отдельно с CDN?

1. файл лежит в статике (свой каталог ассетов, MinIO, позже CDN);
2. в Markdown — обычный URL: `![](/course-assets/html/intro/box-model.webp)`;
3. браузер качает картинку **вторым запросом**, со своим кэшем и `Cache-Control`;
4. в уроке реализовать lazy-load, а формат картинки WebP.

Пока это не реализовано. Оставил на будущее.

## Что будет, если добавить видео

Все, тоже самое, что и с картинками. Отдельный СDN.

## Как ускорить доставку контента

**1. Через sync любая правка урока доезжает до стенда медленно**.

- считать хеш файла и обновлять только то, что изменилось;
- писать в БД пачкой, не по одному уроку;
- чистить «сирот», которых уже нет в файлах;
- разбить media и картинки по разным контурам;

**2. Через API урок открывается медленно**.

По порядку, без магии:

1. **Не раздувать тело урока.** Markdown в `content`. Картинки и видео — отдельный URL.
2. **Статика своим кэшем.** Долгий `Cache-Control` на ассеты, короткие заголовки или ETag на JSON урока. После sync сбрасывать только то, что связано с уроками, не весь Redis.
3. **Redis — после тонких ответов.** Middleware уже написан, но к урокам не подключал. Ответ зависит от пользователя (записан ли на курс, открыт ли следующий урок). Общий кэш на всех быстро врёт. Сначала тонкий JSON, потом кэш с нормальным сбросом после sync.
4. **Рендер оставить на клиенте**, пока тексты урока небольшие. Собирать HTML при sync имеет смысл только если теория реально станет простынёй. Сейчас боль — лишние поля в оглавлении.
5. **Медиа не через API приложения.** Картинки и видео — nginx / MinIO / CDN. API отдаёт ссылки. Браузер качает файлы параллельно с текстом, а не внутри него.

## Итого

1. sync только изменённых файлов (хеш);
2. убрать решения и тесты из оглавления;
3. отдельная поставка ассетов для картинок (URL в Markdown, файлы не в `content`);
4. потом кэш API с сбросом после sync;
5. видео и картинки — отдельным URL`.

Отдельно в планах — вынести `course-content` в отдельный контур. Подключить к админке для работы с уроками.
